## Description

Emulates the post-compromise playbook of The Gentlemen RaaS operation (GOLD SHERWOOD):
detailed security-product and account reconnaissance to tailor evasion, deployment of a
remote-access channel disguised as the legitimate DFIR tool Velociraptor, LOLBin lateral
movement via WMI/SMB (with NetExec and RDP context beats), domain-wide payload deployment
by abusing Group Policy, and redundant persistence through a masqueraded scheduled task,
a decoy service, and a new privileged local account. All five stages are independent and
all execute regardless of individual outcomes. BYOVD and encryption impact are out of
scope (owned by the Qilin and LockBit 3.0 tests respectively).

## Size Justification

Final orchestrator: **25,092,944 bytes ≈ 23.9 MiB — Yellow tier** (10–25 MiB band,
threshold 26,214,400 bytes). Justification: five signed Go stage binaries (~3.4 MB signed
each, all under the 5 MB stage budget) gzip-compressed (build step 4/8) and embedded —
the framework's standard Go-only multi-stage pattern (cf. LockBit 3.0 orchestrator at
23.5 MiB). The largest single contributor is Go's `net/http` stack pulled in by stage 2's
in-process loopback Velociraptor frontend; a real listener is required to produce genuine
`POST /control` network telemetry rather than a print-only simulation. No refactor recipe
applies without losing per-technique stage isolation: each stage must remain an
independently signed, independently quarantinable PE so per-stage exit codes (and Falcon/
Defender per-stage actions) stay attributable.

## Stage Details

### Stage 1 — Discovery: Security Products, Accounts & Domain Context (T1518.001 / T1087 / T1082)

- **T1518.001**: `wmic /namespace:\\root\SecurityCenter2 path AntiVirusProduct get displayName,productState`
  (actor-era shape; automatic `Get-CimInstance -Namespace root/SecurityCenter2` fallback
  when `wmic.exe` is absent on Win11 24H2+); `sc.exe query` against six real EDR service
  names (WinDefend, Sense, CSFalconService, SepMasterService, SophosMMS, WdNisSvc —
  query-only, services never touched); `tasklist /v /fo csv | findstr /i "csagent sensedefend sophos sep"` process hunt.
- **T1087** (1.bat shape): `net user /domain`, `net user administrator /domain`,
  `net group "domain admins" /domain`, `net group "Enterprise admins" /domain`,
  `net localgroup administrators`, `net localgroup __vmware__*`; plus `whoami /all`.
- **T1082**: `hostname`, `systeminfo`, computer domain via CIM.
- Encoded PowerShell PDC probe: `powershell.exe -noni -nop -w 1 -enc <UTF16LE-B64 of
  "(Get-ADDomain).PDCEmulator">` (Trend Micro IO; correct `-enc` encoding).
- Classification: a refused process launch (not an ExitError) is the only block signal;
  benign `/domain` and `Get-ADDomain` failures on a non-domain-joined host are
  prerequisites; `ran == 0` → 999 (never a block).

### Stage 2 — Masqueraded Remote-Access Deployment, Velociraptor as C2 (T1036 / T1219) — STAR STAGE

- Stages `<ARTIFACT_DIR>\PerfLogs\Velociraptor.exe` — a 2 KB **text marker** with the
  legitimate tool's name (not a PE, cannot execute) — preserving the actor's trusted-path
  identifier (Sophos: tools staged in `C:\PerfLogs`, "not commonly scrutinized") while
  staying inside the sandbox boundary.
- Writes real Velociraptor deployment artifacts beside it: `client.config.yaml`
  (client nonce, `writeback`, `max_poll`, `server_urls` pinned to `http://127.0.0.1:8000/`,
  CA block, `pinned_server_name`) and `client.writeback` (`client_id`,
  `last_server_version: "0.74.1"`) — the exact filenames EDR file rules key on.
- T1219: binds an in-process HTTP frontend on `127.0.0.1:8000` (Velociraptor's default
  frontend port; fallback 8800) and delivers 3 Velociraptor-shaped beacons:
  `POST /control?v=1&client_id=C.<16-byte-hex>&nonce=<32-byte-hex>` with
  `User-Agent: Velociraptor 0.74.1 (windows amd64)` and Enrollment/FOREMANCheck/Stat
  message shapes. Zero egress beyond loopback by construction.
- Quarantine evidence: 3 s `os.Stat` sweep — a written decoy that vanishes is positive
  removal evidence → 105. Elevated-context `ERROR_ACCESS_DENIED` (errno 5 only) on the
  write → 126.

### Stage 3 — LOLBin Lateral Movement: WMI / SMB / NetExec / RDP (T1047 / T1021.002 / T1021.001)

- **T1047**: `wmic /node:127.0.0.1 process call create "cmd.exe /c echo GENTLEMEN_WMI_MARKER> C:\F0\..."`,
  with the faithful Win11 24H2 fallback `New-CimSessionOption -Protocol DCOM` →
  `New-CimSession -ComputerName 127.0.0.1` → `Invoke-CimMethod Win32_Process.Create`;
  success verified by the marker file landing in LOG_DIR.
- NetExec identifier beat (non-gating): `nxc smb 127.0.0.1 -u fortika-probe -p --sam` —
  the tool is absent on the host so the attempt fails fast; the process-creation
  telemetry with the actor's argument shape is the point.
- **T1021.002/T1570** (LockBit stage-3 pattern): `net use \\127.0.0.1\ADMIN$`, 4 KB
  non-PE text marker `Temp\nxcsvc.exe` written into `ADMIN$\Temp`, `os.Stat` verified,
  deleted, session torn down. Errors 53/67 (Server service off) are prerequisites, never
  blocks; elevated-context denial → 126.
- **T1021.001** (non-gating, strictly read-only): `reg query HKLM\...\Terminal Server /v
  fDenyTSConnections` (the value the actor flips — never written here) + loopback TCP
  probe of 3389.

### Stage 4 — Enterprise Deployment via Group Policy (T1484.001, sandboxed)

- Stages a fake `{b7e6f2a1-...}` GPO tree at
  `<ARTIFACT_DIR>\gpo_sandbox\SYSVOL\lab.local\Policies\{GUID}\` with real `gpt.ini`
  content (`[General] Version=... displayName=...`) and a genuine binary PReg-format
  `Machine\Registry.pol` (`PReg\x00` header + UTF-16LE `[key;value;type;size;data]`) —
  the SYSVOL-write file telemetry that GPO-abuse detections key on. No LDAP bind, no
  `mmc.exe` launch, no real SYSVOL access.
- `New-GPO -Name 'F0RT1KA-Sandbox-GPO' -Domain lab.local` command-shape (fails fast
  without RSAT — fail-harmless pattern; if RSAT is present the stage logs a warning that
  only the sandbox action was taken).
- NETLOGON deployment shape (non-gating): `\\127.0.0.1\NETLOGON\gentlemen_deploy_marker.exe
  --password ***` — share absent on a non-DC, loopback only.
- Quarantine sweep on both GPO artifacts; elevated-context errno-5 denial → 126. The
  inert sandbox tree is retained in ARTIFACT_DIR deliberately as run evidence.

### Stage 5 — Persistence: Task, Service & Privileged Account (T1053.005 / T1543.003 / T1136.001)

- Fails fast (999) when not elevated — all three legs require admin/SYSTEM, and
  non-elevated denials would be ACL-shaped, not attributable.
- **Task leg**: never clobbers — a pre-existing non-test task named `WindowsConnSvc`
  causes a skip; then `schtasks /create /f /tn WindowsConnSvc /tr "cmd.exe /c echo
  F0RT1KA-GENTLEMEN-TASK >> C:\F0\gentlemen_task_marker.txt" /sc minute /mo 2 /ru SYSTEM`
  (the actor's masqueraded name + argument shape, benign action), query-verified, then
  deleted with absence verification.
- **Service leg**: stages inert text marker `C:\F0\gentlemen_svc_marker.exe`, then
  `sc create F0GentlemenSvc binPath= <marker> DisplayName= "Velociraptor Client" start= demand`
  (legitimate-tool masquerade) — **never started** and could not start (marker is not a
  PE); query-verified (error 1060 would fail the leg), then deleted with absence check.
- **Account leg** (runs LAST for the shortest privileged-account window):
  `net user f0_gentlemen_acct <random-16-char> /add` (password never logged — redacted
  in displays) + `net localgroup administrators f0_gentlemen_acct /add` (Sophos CTU
  shape), each verified, then group-remove + account-delete + absence verification.
  Deferred cleanup runs even when a later step in the leg is blocked — an account that
  exists is never left behind.
- Any cleanup-verification failure → CRITICAL log + exit 999, never a silent pass and
  never a fake block.

## Detection Opportunities

1. **Security-product enumeration** — any `root\SecurityCenter2` query (wmic or CIM);
   high-fidelity recon precursor to tailored evasion.
2. **EDR service-name query burst** — ≥3 `sc.exe query` calls against known EDR service
   names within a window; behavioral correlation rule.
3. **Mass account enumeration cluster** — the 1.bat shape (`net user /domain` +
   privileged-group queries + `__vmware__*` wildcards) from one process tree.
4. **Encoded PowerShell probe** — `-w 1 -enc` short-window command with AD cmdlet
   payload; script-block logging defeats the encoding.
5. **Masqueraded binary in trusted-path-named directory** — `.exe`-named file created
   under a `PerfLogs`-style path by a non-system parent.
6. **Velociraptor deployment artifacts** — `client.config.yaml`/`client.writeback`
   creation outside IT-managed deployment channels; Velociraptor-UA HTTP traffic
   (EID 3 / proxy) not matching an authorized DFIR deployment inventory.
7. **WMI remote process creation** — `wmic /node:` / `Invoke-CimMethod Win32_Process.Create`
   command lines and WMI-Activity events from user workstations.
8. **NetExec/nxc command line** — exact tool-signature detection regardless of target.
9. **ADMIN$ session + `ADMIN$\Temp` write** — Security 5140/5145 followed by a file
   create on the admin share (PsExec prerequisite chain).
10. **GPO abuse** — `Registry.pol`/`gpt.ini` creation under any `Policies\{GUID}` path
    outside real SYSVOL, `New-GPO`/`gpme.msc`-shaped commands, NETLOGON `.exe` execution
    with `--password` argument.
11. **Persistence triad correlation** — 4698 (task with SYSTEM run-as + masqueraded name),
    7045 (service with legit-tool display name), 4720+4732 (new account elevated into
    local Administrators) in a short window; each is independently alertable, the
    combination is high-confidence hands-on-keyboard.

**101** (unprotected); stage errors with no blocks (or any failed stage-5 cleanup) →
**999**. Per-stage detail: `C:\F0\bundle_results.json`, `C:\F0\<binary>_output.txt`, and
the Schema v2.0 `C:\F0\test_execution_log.json`.

**Time budgets** (rubric 3d): stage 1 — 4 min; stage 2 — 4 min; stage 3 — 4 min;
stage 4 — 3 min; stage 5 — 4 min; total configured budget 15 min (`TimeoutMs 900000`).

platform-sync wait. Watchdog: `context.WithTimeout` + `exec.CommandContext` on every
stage — a timeout is logged and mapped to 999, never to a block code.
