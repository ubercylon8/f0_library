## Classification decision tree (101 / 105 / 126 / 999)

```
prerequisites not met (Defender off | Server SKU | no interactive token)        -> 999
baseline System32\wermgr.exe hash unreadable                                    -> 999
dropped RoguePlanet.exe removed from LOG_DIR within 3s (os.Stat)                 -> 105
RoguePlanet.exe disappears mid-loop (os.Stat)                                    -> 105

    (ERROR_VIRUS_INFECTED/DELETED, or ACCESS_DENIED on confirmed-present file)   -> 126
success marker "Exploit succeeded." AND wermgr.exe hash deviated from baseline   -> 101
otherwise (lost race / benign launch failure / no positive evidence)            -> 999
```

Rule 8 compliance: there is **no catch-all that resolves unknown failures to a block
code**. The default verdict is `clsInconclusive` → 999. A benign launch error
(e.g. a token failure, a missing interactive session) is explicitly classified
inconclusive, never "prevented."

## SYSTEM → non-elevated-user token drop (load-bearing)

RoguePlanet's `main()` branches on `IsRunningAsLocalSystem()`: as SYSTEM it takes the
re-entry path and never runs the exploit. Prelude/Achilles frequently run
orchestrators as SYSTEM. `launcher_windows.go` therefore:

1. `isSystemContext()` — compares the process token user SID to `WinLocalSystemSid`.
2. If SYSTEM: `WTSGetActiveConsoleSessionId` → `WTSQueryUserToken` →
   `DuplicateTokenEx` (primary token) → `CreateEnvironmentBlock` →
   `CreateProcessAsUser` into `winsta0\default`, `CREATE_NEW_CONSOLE`. stdout/stderr
   are captured via an **inheritable file handle** to `C:\F0\RoguePlanet_output.txt`
   (Rule 5) — the only reliable way to capture a child running in another session.
3. If normal user: `CreateProcess` directly with the same inheritable output handle.
4. If no active interactive session / token unavailable: prerequisite failure → 999.

## Race handling

Bounded by **both** an attempt cap (`MAX_ATTEMPTS = 5`) and a wall-clock budget
(`OVERALL_BUDGET = 5 min`), justified by COMPLEXITY=high. The loop exits early on the
first confirmed 101 (success) or 105/126 (block). During each attempt the orchestrator
**polls `wermgr.exe`'s hash every 750 ms** so it catches the transient success window
before the ~30s self-restore reverts the file — it treats **any** observed deviation
from baseline as the change signal and does not rely on the post-restore hash.

## Design notes & caveats

### Signing tradeoff (explicit)

The embedded `RoguePlanet.exe` is signed with the F0RT1KA certificate before embedding
(standard suite signing). **This may suppress the very AV/EDR reaction the PROTECTED
branch is meant to measure** — ASR rules and reputation/whitelisting can treat a signed
binary differently than an unsigned one. To keep block-detection meaningful against a
signed payload that behavioral rules still dislike, the orchestrator keys PROTECTED on:

- **quarantine of the dropped file** (`os.Stat` disappearance), and
- **OS-emitted execution-prevention** at launch,

rather than on signature-based pre-execution blocks alone. Operators who specifically
want to measure unsigned-binary reputation blocking can rebuild with signing disabled
(remove the F0RT1KA sign step in `build_all.sh`); the orchestrator logic is unchanged.

### Real detonation / cleanup

- Overwrites `System32\wermgr.exe`; PoC self-restores after ~30s, leaving
  `wermgr.exe.rp_old` until reboot. Phase 4 re-hashes `wermgr.exe` and, if it does NOT
  match baseline, logs a CRITICAL with manual-restore guidance
  (`%TEMP%\RP_wbk_*`, needs elevation — see analysis §10).
- The spawned SYSTEM console persists (intentionally not killed; out of scope).
- Dropped `RoguePlanet.exe` and `RoguePlanet_output.txt` are removed in cleanup where
  possible.

### Prerequisites

- Windows client SKU (not Server — standard users can't mount ISOs there).
- Defender real-time protection ON (it is the target).
- An active interactive console session (for the user-token drop).
- 4+ vCPUs improves race odds (enables the PoC's "Poseidon" noise threads) but is not
  enforced.
