## Size Justification

**Binary size: 16.0 MB (16,753,208 bytes) — Tier: 🟡 Yellow (10–25 MB).** SHA1 varies per build (e.g. `c770e6dae8331de47fcc1cf810f130ba257b91f1`) because gzip embeds an mtime-sensitive header — the size and behavior are stable; sign/hash the specific artifact you deploy.

The orchestrator embeds six independent Go stage binaries. Each Go ELF carries its own copy of the runtime plus the shared `test_logger.go` (Schema v2.0 logger ~42 KB of source compiling to a substantial object) and the Prelude endpoint library, so each uncompressed stage is ~5–6 MB. Gzip compression is correctly wired (build_all.sh Step 4): the six compressed blobs plus the orchestrator's own runtime land at 16.0 MB, versus ~24–28 MB uncompressed — gzip keeps the test out of the Red tier.

The size is justified by the test's fidelity requirement: the campaign is a genuine 6-technique kill chain and each stage is anchored to a distinct MITRE technique (no speculative stages — see Stage Detail). None of the Red-tier refactor recipes apply: there is no .NET runtime to trim (pure Go), no bulk payload to externalize to `lab_assets/` (stages are loader logic, not data), and stage-splitting would lose technique-level detection precision. 16.0 MB is comfortably within the agent's `MaxDownloadTimeout` envelope. No further action required for Yellow tier beyond this justification.
