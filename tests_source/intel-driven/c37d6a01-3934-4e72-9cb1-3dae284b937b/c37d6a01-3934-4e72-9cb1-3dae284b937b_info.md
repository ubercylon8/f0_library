## Purpose

Kothamine (reported by Microsoft Threat Intelligence, 2026-09-28; technical analysis by Malwarebytes) is malware distributed via malicious npm packages that routes its C2 through Tailscale's `tailcat` — a control-plane-less netcat that carries traffic over the WireGuard data plane via Tailscale's internet DERP relays. Because the traffic is genuine WireGuard to legitimate Tailscale infrastructure, it evades traditional network detection and TLS-inspection controls. This test gives defenders a safe, controlled workload that reproduces the full observable primitive chain — tool transfer from GitHub, DERP-relay tunnel bootstrap, unauthenticated SSH over the tunnel, and data exfiltration over the C2 channel — using the *actual* tailcat binary, so sensor coverage can be measured against real-world telemetry rather than a synthetic approximation.

## MITRE mapping rationale

**T1105 — Ingress Tool Transfer** (stage 1)
- Kothamine builds download Tailscale/tailcat networking components from GitHub at runtime. Stage 1 downloads the pinned tailcat v0.7.0 release asset (zip on Windows, tar.gz on Linux), SHA256-verifies it against authoring-time pinned checksums, extracts it into `LOG_DIR`, and executes `tailcat --version`.

**T1572 — Protocol Tunneling** (stage 2)
- `tailcat serve no-auth-ssh` wraps an SSH server in tailcat's WireGuard data plane with NAT traversal via DERP relays — encrypted C2 that requires no Tailscale account, no control plane, and no open inbound port. This is the core Kothamine evasion primitive.

**T1021.004 — Remote Services: SSH** (stage 2)
- The stage connects back over the tunnel as a client (`tailcat ssh <addr> whoami`) and proves interactive shell access by comparing the remote identity to the local one. Mapped to lateral-movement SSH usage of the established channel.

**T1005 — Data from Local System** (stage 3)
- A fictitious user file set (customer records, payroll, credential notes, contracts) is created under `ARTIFACT_DIR` and collected for staging. Data is synthetic by construction (see Safety Gate rationale).

**T1041 — Exfiltration Over C2 Channel** (stage 3)
- Decoy files are exfiltrated via `tailcat cp` (system scp routed through the WireGuard tunnel, egressing through DERP relays) to an in-test `tailcat recv` drop box. Exfiltration rides the same C2 channel established in stage 2 — the defining characteristic of T1041 vs T1567 (exfil to a *new* web service).

## Detailed stage behavior

### Stage 1 — T1105 Ingress Tool Transfer (tailcat download)

1. Resolves the pinned release asset for `runtime.GOOS/runtime.GOARCH` from the authoring-time table (Windows amd64/arm64, Linux amd64/arm64) with pinned SHA256
2. HTTP GET (180 s client timeout) of the asset from `github.com/tailscale/tailcat/releases/download/v0.7.0/…` into memory (64 MB cap)
3. SHA256 verification against the pinned checksum — mismatch is a prerequisite failure (999), never a block verdict
4. Writes the archive to `LOG_DIR`, extracts `tailcat.exe` / `tailcat` (zip / tar.gz) with mode 0755
5. Quarantine settle check: 3 s sleep, then `os.Stat` — disappearance is positive quarantine evidence (105)
6. Executes `tailcat --version` (30 s timeout); OS denial on exec maps to 126; binary vanishing during exec maps to 127 (both `os.Stat`-confirmed); output must contain the pinned version string
7. Archive removed via defer; extracted binary remains in `LOG_DIR` for stages 2–3

### Stage 2 — T1572 Protocol Tunneling + T1021.004 SSH over tailcat

1. Prerequisites: tailcat binary present (stage 1 artifact), system `ssh` client in PATH (`tailcat ssh` drives it via ProxyCommand) — missing either is 999
2. Runs `whoami` locally to establish the expected identity
3. Launches `tailcat serve no-auth-ssh` as a child; stderr scanned for the ephemeral `tc…` address (regex `tc[A-Za-z0-9_-]{30,}`); 90 s DERP bootstrap budget — no address means egress unavailable (999, ambiguous, never a block)
4. Connects back: `tailcat ssh <addr> whoami` (60 s budget); output must contain the local identity
5. Server killed explicitly after proof and again via `defer` (dies even on panic); kill wait bounded at 5 s; measured server lifetime ~1 s

### Stage 3 — T1005 + T1041 Collection and Exfiltration over the C2 channel

1. Prerequisites: `ARTIFACT_DIR` provisioned/writable, tailcat binary present, system `scp` in PATH — failures are 999 with printed remediation commands
2. Creates 5 decoy files (`Documents/customer_records.csv`, `Documents/payroll_q3.csv`, `Documents/credential_notes.txt`, `Documents/contracts/vendor_msa_draft.txt`, `Desktop/travel_itinerary.md`) with canary-safe content and a run-unique marker; cleanup deferred on every exit path
3. Quarantine settle check: 3 s sleep, re-`os.Stat` every decoy — disappearance is positive block evidence (126)
4. Hashes every decoy (SHA256 source set)
5. Spawns in-test receiver `tailcat recv <LOG_DIR>/inbox` (the attacker's drop box); 90 s address budget; killed via defer
6. Exfiltrates with one `tailcat cp <files…> <addr>:` invocation (120 s budget) — individual file args because the flat write-only drop box rejects recursive copies
7. Verification: 2 s flush settle, then SHA256 hash-set comparison of the receiver inbox against the source set (receiver renames uploads, so content — not names — is compared). Full match = success; partial/no match without positive block evidence = 999 (ambiguous, never a block)

## Execution context (v2.1 criterion 2d)

The test emulates Kothamine's agent, which runs in **standard user context** — no elevation is required or attempted by any stage. The test is context-independent by design: it behaves identically as user, admin, or SYSTEM, and the stage-2 identity proof (`tailcat ssh <addr> whoami` vs local `whoami`) self-adjusts so the recorded telemetry always reflects the true execution context (e.g., `nt authority\system` when run under ProjectAchilles). The only privilege-sensitive operation is one-time `ARTIFACT_DIR` provisioning, which fails closed (exit 999 with printed elevated remediation commands) rather than escalating.
