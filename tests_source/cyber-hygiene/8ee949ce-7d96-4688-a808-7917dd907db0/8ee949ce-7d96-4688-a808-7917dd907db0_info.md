## Description

The bundle evaluates 35 shared Windows baseline controls and six Sophos Intercept X controls, for 41 controls total. It collects local registry, CIM, service, executable-version, audit-policy, and account-policy evidence without changing security configuration or executing attack techniques.

Three Sophos controls use local evidence. Three others—effective prevention policy, recent cloud check-in, and tamper protection—require central management evidence and are deliberately `UNKNOWN` in the standalone binary. ProjectAchilles may evaluate those controls only with endpoint-specific Sophos Central evidence; tenant-wide information is not a substitute for effective policy on the endpoint.

The result is a point-in-time assessment against this bundle's stated expected values. It is not a CIS certification, a complete Sophos Central compliance audit, or proof that the mapped attacks were blocked.

## Technical Details

### Execution Flow

1. **Initialization**
   - Creates `C:\F0` when necessary, resolves the organization, discovers endpoint context, and initializes Schema v2.0 logging.
   - Configures a 600000 ms (10-minute) execution budget and starts a `time.AfterFunc` watchdog. On expiry it logs the timeout, saves the execution log, and exits 102.

2. **Windows baseline assessment**
   - Evaluates 35 controls across registry policy, SMB, network protocols, PowerShell, LSASS, LAPS, Print Spooler, audit policy, and account policy.
   - Shared PowerShell and command helpers use 30-second timeouts.

3. **Sophos assessment**
   - Queries `Sophos Endpoint Defense Service` and `Sophos MCS Agent` through `Win32_Service`.
   - Looks for a readable file version at known Sophos endpoint installation paths.
   - Creates central-only prevention, recent-check-in, and tamper-protection controls as `UNKNOWN`.

4. **Finalization and output**
   - Finalizes each control before printing its console status, then finalizes aggregate bundle status.
   - Writes `bundle_results.json`, `test_execution_log.json`, and `test_execution_log.txt` under `C:\F0`.

For registry-backed baseline controls, a missing policy value generally means `FAIL` / “Not configured”; access or query errors produce `UNKNOWN`. That distinction avoids presenting an unreadable system as evidence of a disabled setting.

### Key Indicators and Side Effects

- Read-only HKLM registry queries and local CIM queries.
- Local `powershell.exe`, `auditpol`, `net`, `sc`, `cmd`, and `secedit` query processes.
- A temporary `C:\F0\f0_cyberhygiene_secedit.inf` security-policy export, removed by the password-complexity check on normal returns.
- Result and log writes under `C:\F0`.
- No payload drops, security-policy changes, account/service creation, credential access, or network egress.

### Execution Context and Time Budget

The test records username and admin status and discovers workstation/server/domain-controller role plus domain and Entra join state. It does not require SYSTEM specifically and does not emulate a separate attacker context. Elevated execution is recommended to reduce avoidable `UNKNOWN` results.

The assessment watchdog is enforced for 10 minutes after logger initialization and exits 102 on expiry. Shared PowerShell and command helpers have 30-second per-query timeouts. Endpoint discovery and logger system-information capture run before the watchdog starts, so those setup operations remain outside its coverage.

## Detection Opportunity Audit

This bundle has six distinct assessment/telemetry surfaces. These are opportunities to validate evidence and collection health, not claims that Sophos or another EDR should generate attack alerts for a hygiene scan.

| # | Surface | Sensor / evidence source | Assessment or rule pattern |
|---:|---|---|---|
| 1 | Security policy registry | Windows registry and endpoint telemetry | Compare the named value with the control's expected threshold; missing and unreadable values remain distinct outcomes. |
| 2 | Sophos and Spooler services | Local CIM `Win32_Service` | Match exact service name, Running state, and Auto start; retain service path as supporting Sophos evidence. |
| 3 | Local Sophos executable version | File metadata through PowerShell `Get-Item` | Match known installation paths and record the readable version; never infer update currency from presence alone. |
| 4 | Windows audit and account policy | `auditpol /get /r`, `net accounts`, `secedit /export` | Parse required Success/Failure modes and configured numeric policy bounds; query errors are `UNKNOWN`. |
| 5 | Adapter and endpoint context | CIM network adapter, OS, computer-system, and join-state evidence | Apply NetBIOS, LAPS, and Spooler logic only to applicable endpoint contexts. |
| 6 | Sophos Central policy and health | PA central evaluator with endpoint-specific API evidence | Resolve prevention, `lastSeenAt`, and tamper state only for that endpoint; do not derive effective policy from tenant-wide summaries. |

No bundled tenant detection rule or lab rule-firing claim is made. Structured per-control results are the primary output signal. The successful lab run verifies control reachability and result plumbing, not tenant detection efficacy.

## Expected Results

### Compliant Controls

- Status `PASS`, `compliant=true`, per-control exit code 126.
- The observed value meets the stated criterion. This does not mean an attack was launched or blocked.

### Non-Compliant Controls

- Status `FAIL`, `compliant=false`, per-control exit code 101.
- At least one failure makes the bundle `non_compliant` and produces overall code 101, even when other controls are incomplete.

### Incomplete or Inapplicable Controls

- `UNKNOWN`, `SKIPPED`, `ERROR`, or `NOT_EVALUATED` makes the assessment incomplete/partial.
- `NOT_APPLICABLE` is excluded from pass/fail evaluation and does not by itself make the assessment incomplete.
- With no failures but one or more incomplete controls, the bundle is `incomplete`, `partial`, and exits 999.
- With no pass/fail evaluations at all, it is `not_assessed`, `error`, and exits 999.

### Watchdog Timeout

- If the assessment exceeds 10 minutes after logger initialization, the watchdog records the timeout, saves the Schema v2.0 execution log, and exits 102.
- A timeout is an execution outcome, not a compliance pass/fail. A partially written or absent bundle must not be treated as evidence of protection or noncompliance.

### Standalone Sophos Central Limitation

CH-SOP-004, CH-SOP-005, and CH-SOP-006 always remain `UNKNOWN` in the Go binary. Consequently, a standalone run cannot produce the fully assessed `compliant` / 126 state. PA can change that limitation only by supplying endpoint-specific central evaluation; it must not assume compliance from tenant-wide configuration or from healthy local services alone.
